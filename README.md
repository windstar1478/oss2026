### 한 줄 소개

취침 시 잔여 카페인을 계산하고, 실제 수면 체감 데이터와 연관 분석하여 나만의 최적 카페인 컷오프 시각을 찾아주는 스마트 다이어리

### 누가, 언제, 무엇 때문에 불편한가

- 누가: 카페인 섭취가 많은 현대인
- 언제: 늦은 오후나 저녁 시간대에 추가로 카페인을 마시려 할 때, 또는 다음 날 아침 수면 상태를 돌아볼 때
- 무엇 때문에: 지금 마시는 카페인이 밤 목표 취침 시각에 얼마나 남아 수면을 방해할지 정확히 알 수 없고, 자신이 오후 몇 시까지 카페인을 마셔도 숙면할 수 있는지(개인별 컷오프 시각)를 알지 못해 수면 패턴이 지속적으로 망가짐

### 지금은 어떻게 해결하고 있나

- 음료 표면의 총 카페인 함량만 보고 감으로 섭취 시각을 조절하거나, 일단 마신 뒤 밤에 잠이 오지 않아 후회함
- 감으로 섭취 시간을 조절하면 시간에 따른 체내 카페인 감소량(반감기) 계산이나 실제 수면 상태와의 상관관계를 정량적으로 분석해주지 못함

### ChatGPT에게 직접 묻는 것과 무엇이 다른가

- 사용할수록 데이터가 쌓이고 연관 분석이 됨:
대화창에 일회성으로 묻는 것과 달리, 서버 DB에 사용자가 기록한 [카페인 섭취 이력]과 [다음 날 아침 체감 수면 데이터(입면 난이도, 기상 개운함 점수)]가 지속적으로 누적되어 두 지표 간의 상관관계를 그래프와 통계로 시각화함
- 같은 조건이면 항상 동일한 결과가 계산됨:
대화형 AI의 가변적인 답변과 달리, 순수 JavaScript 코드로 구현된 '중첩 반감기 공식'과 '수면 통계 집계 로직'을 통해 오차 없이 정확하고 동일한 수치가 산출되며 유닛 테스트로 검증 가능함

### 가장 먼저 완성할 기능

자연어로 편하게 입력하거나 음료 종류와 섭취 시각, 목표 취침 시각을 입력하면 목표 취침 시각에 남아있는 체내 잔여 카페인 양(mg)을 계산하여 숙면 가능 여부(안전/위험)를 판정해주는 기능

### 계산 규칙 후보 (3개 이상)

- 중첩 카페인 반감기 계산 함수: 섭취량과 경과 시간을 바탕으로 특정 시점의 체내 잔여 카페인 계산
- 목표 취침 시각 수면 위험도 판정 함수: 목표 취침 시각 기준 잔여 카페인이 50mg 초과 시 '숙면 위험', 100mg 초과 시 '수면 불가' 상태로 판정
- 수면 체감 - 카페인 상관 관계 통계 함수: 수면 만족도가 높았던 날(4~5점)의 평균 카페인 컷오프 시각 산출 및 오후 6시 이후 섭취 유무에 따른 '입면 어려움' 응답 비율(%) 계산
- 일일 권장 섭취량 초과 검증 함수: 하루 누적 카페인 섭취량이 성인 권장 기준(400mg)을 초과했는지 검증 및 경고 반환
- 자연어 카페인 입력 파싱 지원 함수: 자연어 문장 입력 시 사전 음료 DB와 매치할 파싱 표준 JSON 생성 규격 검증


### 서버가 맡을 일

- 데이터 저장 및 관리: 사용자가 마신 음료, 섭취 시각, 수면 데이터(체감 입면 난이도, 기상 개운함 점수)를 로컬 JSON 파일에 저장, 조회, 삭제
- RESTful API 제공: 프론트엔드 요청에 따라 마신 이력 제공, 잔여 카페인 계산 결과 및 수면 상관관계 통계 반환
- LLM API 보안 및 연동: API 키를 서버 환경변수에서 안전하게 관리하며, 누적된 통계 데이터를 바탕으로 LLM API를 호출하여 프론트엔드로 전달

### 서버가 LLM을 호출하는 곳

1. 자연어 섭취 기록 파싱  
호출 시점: 사용자가 "점심 12시에 스벅 아아 톨 한 잔, 4시에 핫식스"와 같이 비정형 텍스트로 기록을 입력할 때  
전달 데이터: [사용자 입력 문장, 서버 사전 음료 DB 리스트]  
LLM의 역할: 문장을 분석하여 음료 DB 항목, 용량(카테코리), 섭취 시각을 추출하고 프론트엔드 확인용 JSON으로 변환
2. 주간 인사이트 리포트 조회  
호출 시점: 주간/월간 카페인 섭취 이력과 수면 데이터가 누적되어 리포트를 조회할 때  
전달 데이터: [오후 5시 이후 섭취 빈도, 카페인 섭취일 vs 미섭취일의 '입면 어려움' 응답 비율(%), 평균 기상 개운함 점수(1~5점)]  
LLM의 역할: 누적 데이터를 종합 분석하여 간단한 '나만의 AI 카페인-수면 패턴 인사이트 리포트' 작성

### LLM이 지적한 점 (1~2개)

1. ChatGPT 대비 경쟁력 및 입력 편의성 부족:
사용자가 앱을 직접 열어 드롭다운이나 슬라이더로 섭취·수면 데이터를 기록하는 방식은, 카카오톡이나 ChatGPT 대화창에 비정형 텍스트로 대충 적어 기록하는 것보다 입력 장벽이 높아 대체될 수 있음
2. LLM 사용의 당위성 및 필수성 부족:
주간 통계 리포트에서 단순히 "오후 5시 이후 마신 날 잠들기 어려움 비율이 75%입니다"와 같은 문장을 출력하는 것은 백엔드의 단순 조건문(if-else)과 템플릿 문자열로도 구현 가능하여, 굳이 LLM API를 불러야 하는 기술적 명분이 약함

### 그래서 바꾼 것, 또는 바꾸지 않은 이유

1. 사전 음료 DB 구축: 메모장 혹은 ChatGPT를 이용한 수동 입력 같은 경우에는 정확도가 떨어질 수 있음. 음료 카페인 함량을 임의로 추정하여 계산 오차가 발생하는 한계를 극복하기 위해, 서버에 검증된 사전 음료 DB를 구축하여 정밀도 부분에서 해당 프로젝트의 강점 확보
2. 백엔드 if문으로 처리 가능한 숫자 통계 출력과 LLM의 역할을 명확히 분리함. 데이터가 쌓인 후 "지금 커피 마셔도 될까?"라는 사용자의 실시간 질문에 대해, 서버의 정밀 반감기 잔여 계산량 + 사전 음료 DB 수치 + 누적된 개인 수면 체감 데이터를 복합 분석하여 단순 템플릿으로 대체 불가능한 논리적 맞춤형 행동 조언(가이드라인)을 생성하도록 변경
3. LLM 파싱 기반 자연어 입력 기능 도입: 사용자가 편하게 작성한 텍스트("점심에 스벅 아아 톨, 4시에 핫식스")를 LLM이 사전 음료 DB 및 시각 정보와 매칭하여 JSON 데이터로 변환해 주도록 구현. 이를 통해 입력 장벽을 크게 낮추어 지속적인 데이터 누적을 유도하고, 정확성은 서버 DB 수치로 보장함
